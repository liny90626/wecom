# WeCom Changelog Index

本目录记录 OpenClaw WeCom 插件的版本变更。默认先看本 fork 的近期维护版本；原仓库历史版本保留在后续列表中，便于回溯。

## 本 fork 维护版本

- [`v2.7.260-20`](./v2.7.260-20.md)（发布 tag `released/2.7.260-20`，待推 `fork`）：补强多账号 `default` 别名 fail-closed 与 CLI 错误输出脱敏；`-19` 的路由修正保持不变。新增/受影响聚焦回归通过，既有高负载用例的环境超时见简报。

- [`v2.7.260-19`](./v2.7.260-19.md)（发布 tag `released/2.7.260-19`，已推送 `fork`）：修正 `wecom_mcp -> wecom-cli` 兜底的跨品类方法路由；`msg -> message`、`schedule -> calendar`，`doc` 按方法前缀选择 doc/sheet/smartsheet/smartpage/media，无法证明的映射快速失败。稳定单 worker 全量 56 文件 / 710 用例通过。

- [`v2.7.260-18`](./v2.7.260-18.md)（已由 `-19` 取代；发布 tag `released/2.7.260-18` 已推送 `fork`）：新增官方 `wecom-cli` tool 与 16 个 Skills，固定 `@wecom/cli@1.2.0`，按 bot 隔离凭据、启动预热、严格 argv/输出/超时策略；保留既有 MCP，仅对配置层未就绪和 `851003` 做有界 CLI 兜底，并标注 `via`。全量 56 文件 / 706 用例通过。发布后对抗检查发现跨品类兜底映射不完整，故不再推荐安装该包。

- [`v2.7.260-17`](./v2.7.260-17.md)（发布标签 `released/2.7.260-17`）：`wecom_mcp` 收口的**发布版**（`-15`/`-16` 为未打 tag 的验证版，内容已并入）。`851003` 的根因是**结构性**的——`aibot_get_mcp_config` 签发 `/mcp/robot-doc`「企微机器人文档 MCP」只有机器人自身作用域，后台 apikey 签发 `/mcp/v2/bot/<biz>`「动态文档 MCP」内嵌授权真人用户；两个曾被当作根因的假设（缺身份头、`plugin_version` 降档）均已证伪。新增 **`bot.mcpServers`** 配置项，八个能力全可用；严格对齐官方 MCP 实现（身份头、官方 UA、官方错误码分工、文档授权引导卡片且保留 `help_message` 原文）；`tools/list` 按实测体积以 48KB 限幅；并与官方插件仓库同步事件白名单、`enter_check_update` 版本握手、`auth_change_event` 清缓存。该模块从零测试覆盖补到 31 条。
- [`v2.7.260-16`](./v2.7.260-16.md)（**验证版，未打 tag / 未推远端**）：用真实端点探测后**坐实 `851003` 的根因——两条签发路径指向两台不同的 MCP Server**。后台 `/mcp/v2/bot/<biz>?apikey=…` 是「动态\* MCP」v1.0.5（`doc` 62 个新一代工具），其返回里服务端自报「授权真人用户身份」，说明**授权内嵌在 apikey 里**；而 `aibot_get_mcp_config` 签发的是旧一代、19 个工具且**未绑定真人用户**，因此成员的文档一律 851003，不需真人授权的 `tools/list` 却能过。`bot.mcpServers` 升格为推荐配置，八个能力全部可用且无需额外代码；`tools/list` 限幅按**实测体积**（doc 289KB vs 次大 mail 12.8KB）以 48KB 阈值回归；`initialize` 后打印对端 serverInfo。
- [`v2.7.260-15`](./v2.7.260-15.md)（**验证版，未打 tag / 未推远端**）：`-14` 冒烟失败后的收口。冒烟对照（`list category=doc` 成功 19 个工具、`sheet_get_info` 仍 851003、同 docid CLI 通）把范围锁定为**「这份文档的访问权属于成员，而 MCP 调用没带成员身份」**。修掉两处我自己的问题：①身份来源取错——官方取 OpenClaw core 的 `ctx.requesterSenderId`，我却绕道自己的 registry，工具注册时机可能早于入站记录写入，等于 header 压根没发出去；②漏抄了官方每次请求打印「带没带身份」的诊断行。另撤掉我在 `-13` 自加的 `tools/list` 32KB 限幅——现网只有 19 个工具就触发降级，模型拿不到 `inputSchema` 只能猜参数名。并记录：现网工具名与官方文档不是同一代（`sheet_get_info` vs `sheet_get`），工具层面只能以 `action=list` 实际返回为准。
- [`v2.7.260-14`](./v2.7.260-14.md)（发布标签 `released/2.7.260-14`）：把 `wecom_mcp` **严格对齐官方实现**（参考官方插件 `@2026.7.2` 保留的 `src/mcp/`，1814 行），并找到 `851003 no authority` 的真正根因——**官方每次 MCP 请求都带 `x-openclaw-wecom-userid` 透传发起人身份，我们一次都没发过**；MCP 是「代替成员」操作的，不带身份即 no authority（这解释了 CLI 通而 MCP 不通）。该 header 不在公开文档里，只存在于官方源码。同时：身份取值保留原始大小写（小写会触发 `93006`）、官方 User-Agent + undici fetch、清缓存业务码改为官方 `{850001, 851014}`、新增**文档授权引导卡片**（`doc` 命中 `851013/851014/851008` 时经 `aibot_send_biz_msg` 让企微直推卡片并拦下 help_message）。撤回 `-13` 自造的别名归一与 851003 重试，并更正 `-13` 的根因判断与「企微废弃 MCP」的错误结论。
- [`v2.7.260-13`](./v2.7.260-13.md)（发布标签 `released/2.7.260-13`）：收口「同一个 docid，CLI 读写都成功、`wecom_mcp` 却返回 `851003 no authority`」。根因在边界：`category` 被**原样**当成 `biz_type` 发给企微，而官方取值表里取值与能力名并不同名（`msg` 不是 `message`、`schedule` 不是 `calendar`，表格 / 智能表格 / 智能文档三项与文档**共用 `doc`**）；模型猜出来的品类不在表里，企微不报错、只给回一个没有作用域的 URL，缓存之后每次调用都是 `851003`。现按官方表做边界归一（未知取值仍放行并告警，不写死枚举），缓存键改用归一后的 `bizType`；授权类错误（850002/851003）作废配置重取一次再试并附排查提示。举一反三：业务错误码落日志（此前完全静默）、配置 URL 在日志里脱敏（此前带凭证）、`tools/list` 超 32KB 退回名称索引。该模块此前零测试覆盖，本轮补 28 条 + 4 项敏感性验证。
- [`v2.7.260-12`](./v2.7.260-12.md)（发布标签 `released/2.7.260-12`）：一轮**上游核查**的产出。`@wecom/aibot-node-sdk` 无新版本可升（1.0.7 仍是 latest），但企微 2026-08 重写了整套协议文档，对照后发现三件事：①**被踢下线时插件把断连通知当成用户消息跑了一轮 agent**——企微规定同一机器人只能有一条长连接，新连接会挤掉旧的并先推 `disconnected_event`；SDK 1.0.7 把它和用户事件放在同一条 `event` 通道，本插件不区分类型照单派发，正文成了 `[event:disconnected_event]`、peer 落成 `direct:unknown`，且「被踢」诊断的关键词来自 2.3.9、与 SDK 真实 reason 一个都不匹配，`ws-kicked` 从不落账。现在入口精确匹配该事件、记账后直接返回，**刻意不重连**（否则两个实例无限互踢）。②`undici` 7.28.0 → 7.29.0，清掉 1 个 high（5 条 advisory），产线代码零改动。③主动推送显式带 `chat_type`——官方写明不填时「优先按群聊处理」，而入站帧的 `chattype` 早就决定了 peer；`reply.ts` 两条推送路径都带上，`outbound.ts` 拿不到会话类型故保持不变。
- [`v2.7.260-11`](./v2.7.260-11.md)（发布标签 `released/2.7.260-11`）：收口「思考块过长导致回复失败」与「长任务过程仍在丢失、收尾记录令人困惑」。思考块是唯一没做 wire 安全化的文本——裸 `<` 会让客户端把 `</think>` 当标签吃掉，块不闭合并吞掉答案；同时它按**头部**截断，推理越过上限后每帧逐字节相同、被等值判定静音，气泡就停住不动。现改为走正文同源归一化 + 残留 `<` 中性化，并显示**最新的一段**；正文在场时思考块收紧到 800 字符（两者共用同一帧预算）。长任务侧：流窗一死推送**立刻接手**（消除 6→8 分钟盲区），被企微拒绝的气泡帧视为永久记录、其步骤并入 durable 书签**不再重复推送**，取消「📋 本轮过程记录」，无新内容的状态推送改为静默 5 分钟兜底。消息上限按官方 20480 字节调到约 75%（每段 5000 字符 / 15360 字节，6000 字答案 4 条 → 2 条）。新增沉默看门狗：工具阶段气泡静默 90 秒即重绘并带上计时，8 分钟前用更轻的 `【处理中，已用时X】`。
- [`v2.7.260-10`](./v2.7.260-10.md)（发布标签 `released/2.7.260-10`）：根治「长任务过程在同一个气泡上覆盖刷写、既读不到也留不下」。根因是过程文字被建模成**可变状态**（只存当前步骤、帧帧覆盖、final 不含），而 OpenClaw 源头本就把自述作为一次性有序段落发射；现改为**追加式步骤日志**——气泡按 `1）2）…` 编号追加显示（正文在场时日志限幅，答案预算不回退），推送通道按 durable 书签送增量，final 送达后未持久化步骤以一条「📋 本轮过程记录」推送落档（≥2 分钟且 ≥2 步才推）。相邻同文/前缀延续在源语义层合并为一步，真实重复保留。
- [`v2.7.260-9`](./v2.7.260-9.md)（发布标签 `released/2.7.260-9`）：长任务状态刷新间隔改为 **60 秒**，并根治它忽长忽短、偶尔重复的问题。根因是这条状态有三个绘制者（气泡心跳／冻结刷新／后台推送）却各持一个定时器，相位由最近一次无关事件决定；现在统一到一条以回合开始时间为锚的**绝对网格**，绘制前查询、绘制后回报，名额在发出时占用、仅在证明未送达时归还。实测六种场景的间隔全部严格等于 60 秒，且每格只有一条通道绘制。
- [`v2.7.260-8`](./v2.7.260-8.md)（发布标签 `released/2.7.260-8`）：**净减法版本**。删掉 v5 引入的整条结构化工具进度通道——脱敏之后它只能输出 `🧰 Tool Call: running` 这类零信息量标签，却要占用与正文共享的气泡预算；并把过程文字从「跨 item 累积」改回「当前步骤快照」，根治 v6/v7 两轮去重都没治住的重复段落（OpenClaw 每次工具调用都会给自述分配新的 `itemId`）。连带移除 v6、v7 的两层去重，产线代码净减约 340 行。
- [`v2.7.260-7`](./v2.7.260-7.md)（发布标签 `released/2.7.260-7`）：补齐 v6 未覆盖的整段内部重复、快照局部重叠和脱敏工具标签重复；在 Bot WS 最终瞬态气泡合成层按可见行精确去重，统一覆盖流式、后台状态与主动推送，同时保持 final、reasoning 和正文书签语义不变。
- [`v2.7.260-6`](./v2.7.260-6.md)（发布标签 `released/2.7.260-6`）：修复不同 OpenClaw commentary item 携带完全相同 preamble 时过程气泡重复整句的问题；展示层按完整文本精确去重，保留首个 item 顺序及后续分化更新，不转入思考块，也不改变成功 final 清理瞬态过程的语义。
- [`v2.7.260-5`](./v2.7.260-5.md)（发布标签 `released/2.7.260-5`）：把 OpenClaw item/tool/command/plan/approval/patch/compaction 生命周期净化为可见过程；为动态回调 `req_id` 建立 owner 认领，冲突、重投、缺失 ID、容量耗尽或待 ACK 时 fail closed 到主动推送，根治文件+文字相邻回合覆盖与迟到 ACK 丢消息；同时补齐 Unicode 安全裁剪和瞬态/正文独立书签。
- [`v2.7.260-4`](./v2.7.260-4.md)（发布标签 `released/2.7.260-4`）：恢复并正确合并 OpenClaw preamble；长任务状态统一为绝对 8 分钟首次出现、随后每 15 秒刷新；最终 wire 在 Markdown 规范化、literal think 转义、thinking block 与 completion marker 全部落定后再执行字符/字节分段，且正文书签只推进到当前整帧真实可见的 source prefix。
- [`v2.7.260-3`](./v2.7.260-3.md)（**已撤回的历史候选；tag 与包均已删除，由 v4 替代**）：曾恢复 OpenClaw commentary/preamble，并尝试调整长任务节奏；其历史提交保留，但不再是可发布版本。
- [`v2.7.260-2`](./v2.7.260-2.md)（发布标签 `released/2.7.260-2`）：修复上一轮已完成时 reply operation 在结果分诊前释放所触发的 TOCTOU，不再把已接收的新消息误报为「本次回复投递中断」；同时让 tracked `replyHandle.fail()` 已处理的同一 Bot WS 错误止于 runtime 边界，不再被 frame 边界重复记录。接收判据改用 `onAgentRunStart` / `onTurnAdopted`，未接收的 flagless zero 仍只保留既有一次有界重试且不 drain。
- [`v2.7.260-1`](./v2.7.260-1.md)（发布标签 `released/2.7.260-1`）：长任务反馈改为**时间驱动**——OpenClaw 默认不流式推理，纯工具回合零产出，此前三条反馈通道会同时静默到失败为止；同时堵住一处会**静默销毁完整答案**的取消逻辑（未送达的 final 重试不再被下一条消息销毁）。并合并上游 `YanHaidao/wecom`，版本基线随之推进到 `2.7.260`，构建号按规则从 1 重新计数。
- [`v2.5.110-149`](./v2.5.110-149.md)（发布标签 `released/2.5.110-149`）：文件+文字两个方向都能合并成一个回合（此前先打字会丢附件、先附件会丢指令）；长任务运行中的产出随「正在专注任务中…」提示一起送达而不再被丢弃；并修复一次主动推送（子任务完成通知是常见来源）会永久熄灭该长任务全部进度反馈的缺陷。

> B1 Markdown 表格、B2 长文本分段/去重、B3 长任务与新消息合并等较早 fork 修复，已统一归档在 [`v2.5.110-112`](./v2.5.110-112.md)；reasoning 思考块系列修复见 [`v2.5.110-113`](./v2.5.110-113.md)。
