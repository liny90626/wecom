# OpenClaw WeCom 插件 v2.5.110-146 候选变更简报

## 2026-07-25（未发布候选）

### 审查范围

本轮以 `released/2.5.110-118` 的简单、低等待路径为稳定性参照，对当前 Bot WS 入站合并、OpenClaw 会话接管、回复终态和热重载属主生命周期做了两路 xhigh 对抗审查。目标是保留 v136-v145 已验证的完整回复能力，同时避免额外保护逻辑扩大延迟、重复执行或跨实例状态污染。

### 问题与根因

1. **文件后紧跟文字仍可能丢失文字或重复执行文件。** Bot WS 只短暂缓存媒体帧，普通文字也曾被固定等待；合并事件又只使用文字 `messageId` 去重，企微重投原媒体帧时可能在窗口结束后再次独立进入 OpenClaw。群聊合并键缺少发送者也可能把不同成员的相邻消息拼在一起。
2. **新消息会在确认可接管前提前终止旧任务。** pending 会话准备和 active OpenClaw dispatch 共用同一接管注册时序；若旧 run 正处于不可中断的 final/ACK 阶段，新消息先 supersede 旧 handle、随后自身又因 busy 被拒绝，可能造成新旧两条消息都没有最终结果。
3. **热重载后的旧回复可能继续借用新连接。** ReplyHandle 的 prepare、placeholder、preview、final retry 与真实 core Promise 没有统一绑定 WS runtime owner；旧 adapter 停止后，迟到 retry 可能读取同账号的新 push handle。
4. **busy 重试范围过宽。** 共享 busy helper 同时覆盖 flagless zero-output 和 `noVisibleReplyFallbackEligible`。后者可能代表回合已经执行或转入 deferred continuation，再次 dispatch 会带来重复模型调用、工具副作用或重复并入消息。
5. **第二次 busy 提示投递失败缺少兜底。** dispatcher 直接发送第二轮提示，绕过 orchestrator 既有的 `deliver -> fail` 路径；提示本身失败时会留下无反馈气泡。

### 修复方案

- **入站只等待必要方向**：普通文字立即派发；仅“媒体在前、文字在后”保留 `1s` 合并窗口。群聊键加入 `senderId`，窗口内同媒体重投直接忽略。
- **合并消息完整去重**：合并事件保留文字主 `messageId`，并通过 `dedupeAliases` 登记媒体原始 ID；媒体重投不会再次执行，同时已存在的媒体 alias 不会吞掉新的文字主事件。
- **pending 与 active 分层**：会话尚在 prepare 时只接管上一条 pending；确认旧 run 可释放后才注册 active 并 supersede 旧任务。busy 拒绝新指令时，旧任务仍可正常交付 final。
- **属主生命周期闭环**：adapter owner 贯穿 runtime、dispatcher 和 ReplyHandle。stop/reload 会撤销本地 prepare/core 等待，停止 preview、placeholder 与 retry；旧回复不能使用 replacement WS。无法强制中止的真实 core Promise 仍跟踪到自然结算，owner 仅在它与 final retry 都结束后释放。
- **重试严格限界**：只有“零输出、无 reasoning/tool/progress、无 fallback/deferred 标记且仍存在 active run”的明确未接收结果，才允许一次 `500ms` handoff 重试。`fallbackEligible` 永不重试；第二轮统一由 orchestrator 发送提示并复用失败兜底。
- **等待有界且不进入快路径**：handoff/drain 单代最长 `5s`，不跨代无限叠加；无旧任务的普通文字不增加 timer、网络等待或重试。

### 复现与验证

- 修复前回归用例稳定复现：媒体 alias 重投后二次 dispatch、不同群成员误合并、pending 提前 supersede active、旧 owner 借 replacement WS、永不结束的跨代 drain、fallbackEligible 被错误升级为可重试，以及第二次 busy 提示失败未调用 `fail()`。
- 修复后重点生命周期套件：5 个测试文件、249 个测试全部通过。
- 全量 Vitest：43 个测试文件、467 个测试全部通过。
- `npx tsc --noEmit`、`npm run build`、`npm run verify-dist`、B1/B2/B3 检查和 `git diff --check` 全部通过。
- 验证环境：Node `v24.18.0`，`@wecom/aibot-node-sdk@1.0.7`，本地 OpenClaw `2026.6.11`；生产兼容目标仍为 OpenClaw `2026.7.1`。
