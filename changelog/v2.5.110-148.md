# OpenClaw WeCom 插件 v2.5.110-148 变更简报

## 2026-07-30（v2.5.110-148）

### 审查范围

v147 上线后现网反馈：稳定性与响应速度整体改善，但**偶发仍会出现长任务只回复 `LLM request failed`**。本轮先把这句文案的来源追到 OpenClaw 源码，再修插件侧真正能修的部分；同时按要求优化长任务进行中的提示词。

### `LLM request failed` 的来源（源码级结论）

这句话不是插件生成的，也不是「超时」：

- 模型返回错误后，OpenClaw 用 `formatUserFacingAssistantErrorText`（`errors-XbAR6hS3.js`）生成给渠道看的文案。若分类器无法把原始错误改写成更友好的说法（`rawPassthrough` 为真且不属于 schema 类），它会**无条件丢弃原始错误文本**，只返回固定的 `LLM request failed.`。
- 该文案随后作为 `{ text, isError: true }` 进入回复载荷（`payloads-slKkO7u6.js`），插件收到的就是这一行，**看不到、也无法恢复真实原因**。
- 与 `LLM request timed out.` 不同，这一支不带任何分类（非超时／限流／计费／鉴权），也**不会触发 OpenClaw 的模型回退重试**：一次无法归类的服务端抖动就会结束整个回合。长任务的模型请求次数远多于短任务，所以呈现为「偶发、只在长任务上」。

结论：**失败本身发生在模型服务侧，OpenClaw 有意隐去了细节，插件无法预防也无法看到**。插件能负责的是「失败之后用户还剩什么」，而这正是 v147 没有补完的部分。

### 问题与修复

1. **失败的长任务只剩一行英文（本轮主修）。** 长任务的工作往往全是工具调用，没有任何可见正文；等它失败时企微 ~6 分钟流窗早已关闭，final 只能改走主动推送。而 `resolveStreamFallbackText` 在「用户此前什么都没收到」的分支里原样返回错误文本，于是用户收到的就是孤零零的 `LLM request failed.`——既不知道任务跑了多久，也不知道做过什么。
   → 走推送路线的错误 final 现在带上框架与耗时：`⚠️ 本次任务未完成（已运行 12m30s）：\n\nLLM request failed.`。**推理内容不外泄**：它只在折叠的 `<think>` 块里出现，绝不提升为可见正文。
   → 耗时在首次使用时**快照**：这段文案本身就是重试身份，时间戳漂移会重置已跟踪的分片进度，把用户已经收到的分片再推一遍（该风险已由专门用例钉住）。
2. **失败无从诊断。** 新增 `[wecom-reply] error-final` 日志，记录耗时、正文/思考字数与投递路线（`streamDead` / `ackUntrusted`）与截断后的文案。下次复现时用它的时间戳与 reqId 去对齐 OpenClaw 自己的 `embedded run agent end … rawError=…`，就能拿到被隐去的真实原因。

### 长任务提示词优化

`执行长任务中，当前用时X` 改为：

> 正在专注任务中，请耐心等待尽量不要打断我，若10分钟我未发出任何消息再发消息来咨询，万分感谢。 当前长任务用时X

两处出现的地方同时生效：冻结预览气泡里的状态后缀（每 15 秒刷新）与 9 分钟后的后台推送（每分钟一次）。打断正在运行的回合正是触发会话接管的原因，所以文案直接请用户稍等。耗时格式化拆成 `formatElapsedDuration`，供该状态与失败文案共用。

### 复现与验证

- 现网症状先在模拟环境中精确复现：长任务 + 流窗口过期 + 纯工具工作 + 错误 final ⇒ 推送内容恰好等于 `LLM request failed.`（断言 `not.toBe('LLM request failed.')` 在修复前变红）。
- 重试身份漂移单独复现：让主动推送耗时 3 秒后失败，修复前重试文案由「已运行 1s」变成「已运行 3s」，修复后两次完全一致。
- 全量 Vitest：44 个测试文件、**492 个测试全部通过**（基线 490）。
- `npx tsc --noEmit`、`npm run build`、`npm run verify-dist`、B1/B2/B3 检查链（三项均 READY）与 `git diff --check` 全部通过。
- 验证环境：Node `v24.18.0`，`@wecom/aibot-node-sdk@1.0.7`，OpenClaw **`2026.7.1`**（与生产一致）。

### 已知边界

- **失败的根因仍在模型服务侧**，插件只能改善呈现与可诊断性。要拿到被隐去的原始错误，必须查 OpenClaw 网关日志里同一时刻的 `embedded run agent end … rawError=…`。
- 无法归类的模型错误不会触发 OpenClaw 的回退重试，配置 fallback 模型对这一支**无效**（回退只对已分类的失败生效）。
- 失败文案里不包含推理过程，这是刻意取舍：推理只在折叠块内展示，不提升为可见正文。
- 一旦本轮出现过回执缺失，final 仍固定改走主动推送（v147 的取舍）。
