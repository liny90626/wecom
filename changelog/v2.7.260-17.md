## 一、`851003 no authority` 的根因（结构性，非配置问题）

现网实测证明，两条签发路径指向的是**两个不同的产品**：

| 来源 | 端点 | `serverInfo` | 身份 |
| --- | --- | --- | --- |
| `aibot_get_mcp_config`（机器人长连接） | `/mcp/robot-doc` | **「企微机器人文档 MCP」** | 只有机器人自己 |
| 后台「查看使用方式」的 apikey | `/mcp/v2/bot/<biz_type>` | **「动态文档 MCP」** | **apikey 内嵌授权真人用户** |

服务端 `help_message` 与之完全吻合：「机器人不允许编辑由成员或其他机器人创建的文档」。**不是授权没生效，是产品定位不同。**

一并证伪的两个假设（都曾被我当作根因）：

1. **缺 `x-openclaw-wecom-userid`**——现网日志证明它已发出（`useridFrom=ctx.requesterSenderId`、`userid=linky`），`851003` 一字未变。该头仍照官方带上（零风险），但不是解药。
2. **`plugin_version` 是魔法串导致降档**——改成真实版本号后端点毫无变化，仍是 `/mcp/robot-doc`。

**结论**：`wecom_mcp` 要拿到成员作用域，**必须配 `bot.mcpServers`**（后台签发的地址）。使用者已验证：取消授权再重新授权，apikey **不变**，可安全写入配置。

## 二、本版包含的改动

### `wecom_mcp`

- **`bot.mcpServers`**（`biz_type` → 后台 streamableHTTP URL）：配了就直接用，没配的仍走 `aibot_get_mcp_config`，行为逐字节不变。八个能力（`doc`/`msg`/`mail`/`todo`/`schedule`/`meeting`/`disk`/`contact`）全部可用，**无需额外代码**——传输层与工具层本就是能力无关的。
- **严格对齐官方实现**（参考 `@wecom/wecom-openclaw-plugin@2026.7.2` 的 `src/mcp/`，1814 行）：`x-openclaw-wecom-userid` 身份头（取值来自 OpenClaw core 的 `ctx.requesterSenderId`，保留原始大小写）、官方 User-Agent + undici fetch、官方错误码分工（`{850001,851014}` 清缓存 / `{851013,851014,851008}` 推文档授权引导卡片）。
- **文档授权引导卡片**：`doc` 品类命中授权码时，经 `aibot_send_biz_msg`（`biz_type=1`）让企微直接给用户推卡片；**同时保留 `help_message` 原文**——服务端用 `help_instruction` 明确要求逐字展示，官方 `2026.7.2` 那版把它丢掉了（那版代码早于这个字段）。
- **`tools/list` 限幅，阈值 48KB 来自实测**：contact 0.5KB / msg 5.8 / todo 6.0 / disk 6.4 / schedule 8.8 / meeting 11.4 / mail 12.8 / **doc 289KB**（62 工具）。超限退回名称索引（doc 仅 8.3KB）并列出可用前缀。`-13` 那次按文档估算的 32KB 在旧 Server 的 19 个工具上就误伤、`-15` 因此删除；这次的数字是量出来的。
- **诊断补齐**：`config ready` 打出 `type` / `is_authed`（`is_authed=false` 时直接提示去后台授权，不必等 851003）、`initialized` 打出对端 `serverInfo`（两台 Server 一眼可辨）、`rpc →` 打出本次是否带了身份头、业务错误码连同原始返回落日志、配置 URL 一律脱敏只留 `origin + path`。

### Bot WS（与官方插件仓库同步，文档里没有、只有源码才知道）

- **`enter_check_update`**：企微推这个事件，期望插件回复自身版本（`cmd=ww_ai_robot_enter_event`）。此前我们会把它当成一条用户消息**跑一轮 OpenClaw**。
- **事件改用白名单**：只放行 `enter_chat` / `template_card_event` / `auth_change_event`，其余记一条 info 后跳过。`-12` 只精确拦了 `disconnected_event`，同类问题还漏着；改白名单后，将来企微新增事件类型也不会默认误入 agent 通道。
- **`auth_change_event`**：照常派发，并**作废该账号的 MCP 配置缓存**——成员刚改过「可使用权限」，手上那份配置可能已不对应。

### 版本号一致性

新增 `src/version.ts`，由 `version.test.ts` 与 `package.json` 对账——`PLUGIN_VERSION` 会随 User-Agent 上线到企微，发版漏改会直接变红。
