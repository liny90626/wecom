# v2.7.260-18（2026-08-27，LinKy fork 候选）

状态：本地候选；代码、自测与安装包审计已完成，尚未打发布标签，也未推送远端。

## 目标与根因

上一版 `wecom_mcp` 依赖机器人长连接签发的 MCP 地址。该地址的作用域固定为机器人自身，成员文档访问会返回 `851003 no authority`；官方 `wecom-cli` 则可用插件配置中已有的 `bot.ws.botId` + `bot.ws.secret` 完成成员作用域授权，不需要人工维护 apikey。本版按官方 `@wecom/wecom-openclaw-plugin@2026.8.17` 的 CLI 实现接入，凭据格式仍完全由 `@wecom/cli` 管理。

## 变更

- 新增 `src/capability/cli/`：
  - 引号感知 argv 解析与禁用集，拒绝 shell 组合、环境变量赋值、`--config-dir`/`--home` 以及交互式 `auth`；
  - 只从插件私有 `@wecom/cli` 平台包寻址二进制，拒绝 PATH 上的全局 CLI；
  - `BoundedOutputCollector` 以 64 KiB 限制 stdout/stderr，并避免 UTF-8 边界损坏；
  - 按 `(botId, secret)` 生成 `state/wecom-cli/<safeBotId>-<sha8>` 目录，目录权限 0700；授权短路、并发去重、跨账号全局串行和强制重签 5 分钟冷却；
  - 业务命令按 botId 串行，凭据错误码 `{893999, 853004, 853005, 853000}` 只强制重签并重试一次；
  - 统一处理超时、exit 2、ENOENT/EACCES、输出超限和凭据提示，日志不打印 secret。
- 注册 `wecom-cli` OpenClaw tool，并把官方 16 个 Skills 挂载到插件包；依赖固定为 `@wecom/cli@1.2.0`。
- 增加 Gateway 启动阶段的账号凭据预热；预热失败只记录诊断，不影响既有 Bot/MCP 运行时。
- `wecom_mcp` 默认成功路径保持不变。仅当确定的 MCP 配置缺失/拒绝（配置响应错误、缺少 URL、`is_authed=false`），或业务返回 `851003` 时，对 `action=call` 使用 CLI 兜底并标记 `via=cli-fallback:<reason>`。配置请求自身的网络异常不会被误判为可兜底故障。兜底只使用启动预热已落地的登录态，不在请求路径中触发 `auth init`；`851013/851014/851008`、`45009` 和业务传输层异常不自动重跑，避免非幂等写操作重复执行。
- 新增配置类型：`channels.wecom.cli`，账号级 `cli` 可覆盖 `binPath` 与三个官方联调环境变量；不会接受模型传入的环境变量。

## 红线

不得在插件中复刻 CLI 凭据协议，不得让 Agent 通过 `exec` 运行全局 `wecom-cli`，不得把环境变量或配置目录交给模型覆盖；多账号缺少上下文时宁可失败，不回退默认账号。
