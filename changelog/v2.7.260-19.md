# v2.7.260-19（2026-08-27，LinKy fork 候选）

状态：本地修正候选；待完成全量自测、打包、tag 与 fork 推送。

## 根因

`2.7.260-18` 的 MCP 兜底把 MCP `category` 直接当成 CLI 顶层服务，并只为少数旧文档方法写了特例。但官方能力面明确存在两类不等价名称：MCP `msg` 对应 CLI `message`，MCP `schedule` 对应 CLI `calendar`；同时 MCP `doc` 聚合了 CLI 的 `doc`、`sheet`、`smartsheet`、`smartpage` 与 `media`。因此 `message_aibot_send` 会被错误拼成 `msg message aibot send`，`calendar_schedules_create` 会变成 `schedule calendar schedules create`，`sheet_get` 会变成 `doc sheet get`。

问题只影响 MCP 配置层失败或明确 `851003` 后触发的 CLI 兜底；直接使用 `wecom-cli` tool、凭据隔离、启动预热、Skills，以及 MCP 默认成功路径均不受影响。

## 修复

- `msg` 明确路由到 CLI `message` 并剥离 `message_` 方法前缀。
- `schedule` 明确路由到 CLI `calendar` 并剥离 `calendar_` 方法前缀。
- `doc` 根据 `doc_` / `sheet_` / `smartsheet_` / `smartpage_` / `media_` 选择 CLI 顶层服务。
- 保留仓库已有真实对照证明过的旧 MCP 方法表；其他无法证明的旧方法快速失败，不再用下划线拆分后猜测命令。
- 新增 helper 回归及 MCP `851003 ->` 测试子进程集成回归，断言最终 argv 为 `message aibot send`、`calendar schedules create` 与 `sheet get`。
