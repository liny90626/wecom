# v2.7.260-25（2026-08-29，LinKy fork）

发布标签 `released/2.7.260-25`。两处真机反馈：**同一份答案被发两遍**，以及**「长任务处理中，请勿打断」出现得太早**。

## 一、重复内容

### 1.1 复现

按现网气泡的形状写探针（多条 block + 一条带附件的 final），先复现再动手：

~~~text
PROBE_A occurrences=2  hasMEDIA=true
收到，只评估不动手。
评估完成，报告已生成…核心结论：…      ← 有空行
MEDIA:C:\Users\ylclaw001\.openclaw\media\outbound\report.md
评估完成，报告已生成…核心结论：…      ← 同一份，无空行
~~~

与现网气泡同形：第一份有空行、第二份没有，中间夹着一条本地路径。

### 1.2 根因

**不在插件的渲染层，在 OpenClaw 核心把同一个答案用两种形状交给插件。**

流式的 block 走 `createBlockReplyDeliveryHandler`，它对 `normalizeReplyPayloadDirectives` 写死了 `extractMediaDirectives: false`——`MEDIA:<path>` 原样留在块文本里。而 final 走 `splitMediaFromOutput`，剥掉指令之后还会执行：

~~~js
keptLines.join("\n")
  .replace(/[ \t]+\n/g, "\n")
  .replace(/[ \t]{2,}/g, " ")
  .replace(/\n{2,}/g, "\n")   // ← 所有空行被压掉
  .trim()
~~~

于是插件手上是：块 = 带路径 + 有空行，final = 无路径 + 无空行。`mergeFinalReplyText` 按字节比对，`endsWith` 因为末尾那条 `MEDIA:` 失败，回落到 `mergeReplyText`，前缀判定与 16 字符重叠扫描全部落空——拼接。**整份报告发两遍，中间还漏了一条本地路径给用户看。**

两条后果各自独立成灾：路径外漏是隐私与观感问题；重复是把长报告的阅读成本翻倍。

### 1.3 修复（两层，第二层才是根治）

**第一层，摄入边界**：`stripMediaDirectives` 在 `deliver()` 里对每个 payload 的正文剥掉指令，镜像核心自己的规则——

- 围栏内的样例保留（`scanFenceSpans` 的真实规则：同字符、长度不短于开围栏、其后只有空白才闭合；用布尔量切换会在 ` ```js … ~~~ … ``` ` 这种嵌套样例上错位）；
- 逐 token 只认 https URL 与路径，**裸文件名不在此列**——核心只在整段 payload 上才用裸文件名规则，这正是 `MEDIA: 设计稿 v2.png` 仍能成为附件的原因；
- 一行里指令旁边的字保留（`MEDIA: https://x/a.png 请查收` 必须留下「请查收」），但**恰好一个 token 命中且整段读起来是一条路径**时整行让位（核心会在放弃前重试整段 payload）；
- 非路径的散文保留（`MEDIA: 这是说明文字` 是模型的正文，不是指令）。

**第二层，比对处**：`mergeReplyText` 在字节判定失败后，改用**核心那三条替换本身**（`respaceLikeCore`）再比一次。

第二层是关键。第一层本质上是在复刻一个上游解析器，**只要还依赖字节相等，任何一处规则猜错就等于把整个答案再发一遍**。改成按内容比对之后，剩余偏差最多让某行显示得不好看。

刻意**没有**用「抹掉所有空白」来比：那会把「先给错误缩进、再给正确缩进」的两段代码判成同一段而丢掉后者。核心只做那三条替换，比对就只吸收那三条。

同理也**没有**沿用 `normalizeDedupText`（它连标点与大小写都抹平）：`内存 15GB` 与修正后的 `内存 1.5GB` 会被判成同一段，旧的那份反而胜出。

**书签安全**：当 final 是块的超集时，拼接结果是「保留已发出的字节 + 只追加新增的尾巴」（`offsetAfterSqueezedPrefix` 按非空白字符计数定位切点），而不是整体换成 final 的排版——每条车道都用已投递文本做书签（`lastDeliveredBodySourceText` / `previewFrozenDeliveredSourceText`），整体替换会让书签全部失效，死流后的补发会把用户看过的内容重发一遍。

## 二、长任务提示出现得太早

### 2.1 先说没复现出来的部分

现场描述是「约 2 分钟就出现长任务提示」。**该措辞在 2 分钟出不来，且可以证明**：三条产线里 `nextLongTaskStatusDueAt()` 恒 ≥ `handleStartedAt + BLOCK_PREVIEW_MAX_MS`（5 分钟），40 组场景遍历（死流、丢回执、丢所有权、长正文冻结、纯推理、强制推送…）零命中。

### 2.2 顺着这条线找到的真问题

流窗口早死时 `longTaskStatusGateOverrideAt` 把推送车道的首格拉到 5 分钟，而该车道把措辞写死了，不看时钟：

~~~text
PROBE_C firstLongTask = t=300s :: 1）第9步进展

【长任务处理中，请勿打断，已用时5m00s】
~~~

产品自己的长任务门槛是 8 分钟（`LONG_TASK_STATUS_AFTER_MS`），`v2.7.260-11` 的设计说明也写着「8 分钟前用更轻的 `【处理中，已用时X】`」。**这条推送在说谎，而且早了 3 分钟。**

### 2.3 修复

把措辞变成时钟的纯函数——`formatElapsedStatus` 自己按 `elapsedMs` 选前缀，调用点无权决定：

~~~ts
function formatElapsedStatus(elapsedMs: number): string {
  const prefix =
    elapsedMs >= LONG_TASK_STATUS_AFTER_MS ? LONG_TASK_STATUS_PREFIX : RUN_ALIVE_STATUS_PREFIX;
  return `${prefix}${formatElapsedDuration(elapsedMs)}】`;
}
~~~

不是修一个调用点，是**取消所有调用点跟阈值唱反调的能力**。禁改 34 的 8 分钟绝对阈值未被触动——它管的是无内容的纯时钟推送，这里改的只是措辞归属。

## 三、五条既有用例的期望值变化（不是放宽）

五条断流用例原本断言 5 分钟那条推送**等于**长任务措辞，现改为断言轻量措辞并**追加** `not.toContain(LONG_TASK_STATUS_PREFIX)`——断言比原来强。另一条 8m00s 的用例保持不变：它走回执不可信路径、没有 gate override，首推本就落在绝对阈值上。

## 四、对抗式评审

四轮，八个发现，全部修掉。其中五个是**本次修复自身引入的**，值得记录，因为它们都是同一个失败模式：

| 发现 | 后果 |
|---|---|
| 累积式发块时只归一化最后一块 | 答案仍然发两遍 |
| 一行里指令旁边的字被整行丢掉 | **吞掉模型的正文** |
| 扩展名长度 / `http://` / `file://` / 回溯路径判定与核心不一致 | 路径外漏 + 重复 |
| `normalizeDedupText` 连标点和大小写都抹平 | `内存 1.5GB` 被旧的 `15GB` 覆盖 |
| 带空格的文件名（`设计稿 v2.png`）中段仍重复 | 答案两遍 |
| 围栏切换用布尔量，遇 ` ```js … ~~~ … ``` ` 错位 | 答案两遍 + 路径外漏 |

结论写进了代码注释：**复刻上游解析器是必输的赌局**，所以第二层（按内容比对）才是这次改动的重心。

## 六、一个刻意的取舍

两段文字只差空白时，**已经发出去的那份字节胜出**。好处是所有投递书签保持有效，推送车道不会重发用户看过的内容；代价是模型「先给错误缩进、再给正确缩进」的同一段代码，气泡里留的是前一份。选前者是因为后者会让死流后的补发重复正文——这条可以反过来，属产品取舍而非技术限制。
