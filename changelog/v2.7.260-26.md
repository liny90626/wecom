# v2.7.260-26（2026-09-02，LinKy fork）

发布标签 `released/2.7.260-26`。四件事：**长任务结尾的假状态**（两条独立机制）、**同时运行在 OpenClaw 2026.7.1-2 与 2026.8.2**、**Bot WS 车道两处提速**、以及一批评审与上游对账带来的收口。全部先复现、再修、再用同一用例验证。

## 一、长任务结尾：答案末尾挂着「【长任务处理中，请勿打断，已用时12m24s】」

### 1.1 机制一：推送车道把时钟押在答案身上

复现（`long-task-progress.test.ts`「死窗后的收尾」）：窗口约 6 分钟关闭后，答案正文只能以 block 到达推送车道；推送车道给每条带新内容的推送缀上时钟，final 随后到达时正文已全部送出，只能再补一句「回复已完成」——那行时钟便永远留在答案末尾。现场 12m24s 这种非整分读数正是「死亡时刻 + N×60s」网格的指纹，不是 8m00s 起算的气泡网格。

修法：**带正文的推送不再缀时钟**。正文本身证明回合活着；只带过程步骤、只带思考或什么都没带的推送照旧带钟，禁改 25/34 的 8 分钟阈值与 5 分钟静默节奏未动。

取舍：持续产出正文的长任务，在正文推送之间不会再出现「请勿打断」。

### 1.2 机制二：一次 ACK 丢失让气泡永不 finish

对抗式评审挖出、网关模拟器复现（`gateway-sim.test.ts`「closes an ACK-untrusted bubble…」）：回合中任意一次 5 秒 ACK 超时都会把流标为不可信，final 改走推送；但冻结气泡仍在画时钟，且此后没有任何人给它发 finish 帧。用户看到的是一个**仍在转圈**、末尾是时钟的气泡，下面压着一条「回复完毕」。

修法：answer 推送落地后，对「活着但不可信」的气泡补一帧 best-effort finish，内容是它已显示的那一帧去掉时钟；证明已死的窗口不发，callback claim 到期不发，final 帧已尝试过流的分支不发（那一帧可能已落地，重绘会盖掉答案）。迟到 ACK 确认在 settle 之后也刷新 `lastPreviewText`，否则 finish 帧可能重发更早的一帧、把两帧之间的正文从气泡与推送里同时抹掉。

### 1.3 附带

deferred 与外部送达的收尾把带时钟的最后一帧原样当 finish 内容重发；现在所有 finish 帧都剥掉时钟（`stripElapsedStatusLine`）。正文已全部送达时，收尾推送只发「（回复完毕）」，不再是「最终回复已完成，以上预览内容即为完整回复。」叠加同一个标记。

## 二、同时运行在 OpenClaw 2026.7.1-2 与 2026.8.2

一份构建，不探测版本，不分叉。插件碰到的每个 OpenClaw 接口都在两条线的导出表与类型声明里逐个核对；`src/openclaw-sdk-imports.test.ts` 守住 import 面；`npm run compat:check` 对两条线各跑 typecheck 与全量测试。

| 8.x 变化 | 修法（两条线均验证） |
|---|---|
| 根入口 `openclaw/plugin-sdk` 及约 55 个子路径被删除，插件无法加载 | 54 处 import 迁到两条线都存在的子路径 |
| `config.loadConfig()` 删除 | `getWecomRuntimeConfig()` 走 `current()`，一处边界转换 |
| `assertLocalMediaAllowed` 私有化 | `readLocalFileFromRoots`，同一根策略，配置根同时给出 realpath 形态 |
| `commands.useAccessGroups` 从类型删除、恒为 true | 结构化读取，7.x 仍尊重该开关 |
| 动态 Agent 写名册：旧守卫在 8.x 静默跳过，而 8.x 拒绝运行不在名册上的 agent | `current()` + `mutateConfigFile`，识别 8.x 的 `agents.entries`（`agents.list` 在 8.x 只是只读投影） |
| 真实分发器测试共用固定 `/tmp` 状态目录，8.x 要求对旧库做 SQLite 迁移 | 每次运行独立临时目录 |

8.x 上**操作侧必做**：8.x 拦截非内置插件的 `before_prompt_build` 钩子（我们的媒体、模板卡片与 wecom-cli 指引就挂在这里），安装向导现在无条件写入 `plugins.entries.wecom.hooks.allowConversationAccess: true`（7.1-2 也认识该键，它在 7.x 只管另一组钩子）。已安装的实例升到 8.x 需手动补这一段：

~~~json
"plugins": { "entries": { "wecom": { "hooks": { "allowConversationAccess": true } } } }
~~~

8.x 行为差异（未改代码）：零可见输出的回合，8.x 核心自己投递英文兜底「No reply was generated for this message…」并报告 `noVisibleReplyFallbackDelivered`，7.x 由插件发中文提示；插件对两种形态都处理正确。8.2 有 174 个 SDK 子路径不带类型声明，`file-access-runtime` 是其一，兼容脚本用 shim 补齐。8.2 自己的加载器 `openclaw plugins inspect wecom --runtime --json` 对本包报 `status: loaded`。

## 三、Bot WS 车道提速

- **死窗后正文按 20 秒推送**：新到的正文曾要等共享的 60 秒时钟网格，最多落后一分钟。现在带正文的推送用自己的 20 秒节奏，仍受同一道门槛（回合不满 5 分钟不会变成推送对话）；步骤与纯时钟保持 60 秒网格和 8 分钟阈值；死窗后新到的正文块立刻唤醒推送车道。
- **气泡跟随答案到 5000 字**：预览曾在 3000 字冻结，而一帧流式消息能装 5000 字/15360 字节（final 早已如此）。气泡帧上限抬到 5000 字，冻结阈值随之抬到 5000；推送分片仍是 3500 字。**没有**做滑动尾巴：窗口一死气泡就是永久记录，滑过去的正文要么整段重发要么按前缀书签丢失。B2 门禁字面匹配的 `BLOCK_PREVIEW_MAX_CHARS` 值同步改为 `5_000`，属有意识的决定。
- 顺带发现、未改：正文预览 5 分钟冻结后不再向企微发帧，死窗只能由步骤帧、工具阶段 90 秒心跳或 8 分钟状态帧撞出来；纯正文无工具的回合会等到 8 分钟。可选修法是冻结后每 20 秒发一帧同内容探测帧。

正文首次出现时间最大的一块不在插件：OpenClaw 默认攒够 800 字才交出第一个 block（`agents.defaults.blockStreamingChunk.minChars`），纯配置可调。

## 四、评审与上游对账收口

- 上游 `origin/main` 25 个提交对账：Bot WS 车道没有必须补的修复。移植了两项影响 Agent API 车道的修复（0d85ccb 字节切分、b28611d 1100ms 节流）：message/send 上限是 2048 **字节**，纯中文按字符切会被企微静默截断；相邻分片同秒到达客户端排序不稳。它们不改变 Bot WS 车道，也不提速。
- 兼容改动通过独立评审，两处必修已修：迟到 ACK 与 finish 帧之间的正文丢失窗口（见 1.2）；兼容脚本在 Windows 上通过 shell 调 npm。
