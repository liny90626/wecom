# v2.7.260-4（2026-08-02，LinKy fork 维护版）

发布标签 `released/2.7.260-4`。本版替代已撤回的 `2.7.260-3`，完成 OpenClaw preamble、长任务状态节奏和 Bot WS 最终投递预算的统一修复。

> **版本边界**：本轮仅按生产同版本 OpenClaw **2026.7.1** 验证。`peerDependencies.openclaw` 继续保留 `^2026.6.11`，但本简报不声称执行了 2026.6.11 验证。未执行 `npm publish`。

## 一、长任务状态以回合绝对时间为准

- 首次长任务状态固定在回合开始后的绝对 **8 分钟**，精确文案为 `【长任务处理中，请勿打断，已用时8m00s】`。
- 8 分钟后每 **15 秒**刷新；静默任务、冻结正文预览和流窗口失效后的主动推送使用同一门槛与节拍。
- 成功的初始 placeholder 只发送一次；仅发送失败时沿用 3 秒短重试。
- pending preview、in-flight ACK 或真实正文进度占用单一 ACK 槽时，状态帧不会抢占该槽。
- `BLOCK_PREVIEW_MAX_MS=5 分钟` 仍只决定正文预览何时冻结，不改变 8 分钟门槛。

网关时间线复现并修复了三个组合竞态：`7m59s` 才到达的冻结预览不再把首状态推迟到 `8m15s`；8 分钟状态帧持续丢 ACK 时会在确认不可信后切到主动推送并维持 15 秒 cadence；一次 ACK 丢失已经恢复后，外部活动不会重新武装重复的后台状态通道。

## 二、OpenClaw preamble 保持瞬态、保序且可扩展

- `dispatchRuntimeReply` 通过 `onItemEvent` 只接收 `kind === "preamble"`，并用 `channelData.openclawProgressKind="preamble"` 标记。
- `progressText` 被视为该 item 的当前完整快照：同一 item 原位替换，不再把缩短后的快照错误追加到旧内容；不同 item 按首次出现顺序组合，无 `itemId` 使用匿名 item。
- 慢 ACK 期间仅保留最新待发快照，并在真正出队时懒构造完整文本；10,000 item 回归避免了每个事件重建全量字符串。
- preamble 不进入 `accumulatedText` 或 final，也不因单独可见而抑制 superseded 回合的真实 final。

## 三、最终 wire 预算与正文书签同源

P1 红测在旧实现稳定得到最终 preamble wire **5551 chars > 3500**：代码先按 Markdown 中间表示截断，之后才把 literal `<think>` 扩为 `&lt;think&gt;`。同一顺序问题也影响普通预览、normal final 和 active push。

修复后统一按最终 wire 表示处理：先完成 Markdown 规范化、literal think 转义、真实 thinking block 与 completion marker，再在企微限制内分段。预览结果同时返回生成该 wire 的实际 source prefix，书签不再从转义前文本反推。

由独立红测确认并一并根治的同源问题：

- 大 preamble 或 Fast 全帧覆盖此前正文后，846608 fallback 会漏掉被覆盖的正文片段。
- preamble-only / Fast-only 曾被当成真实正文，导致新消息接管后吞掉旧任务的真实 final。
- error final 的 thinking 前缀曾按 3500 而不是 final 的 2000 字符预算，`finish=true` 帧可越界。
- completion marker 曾可能落在分段编号之前、正文自带 marker 时重复，或 reasoning-only 收口退化为空帧。
