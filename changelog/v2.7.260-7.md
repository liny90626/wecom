# v2.7.260-7（2026-08-07，LinKy fork 维护版）

发布标签 `released/2.7.260-7`。本版补齐 `2.7.260-6` 未覆盖的过程气泡重复形态：整段内部重复行、不同快照局部重叠，以及多个结构化事件脱敏后显示成相同的通用工具标签。

> **版本边界**：开发与自测只使用 OpenClaw **2026.7.1-2**，不执行其他版本或双版本矩阵。`peerDependencies.openclaw` 继续保留 `^2026.6.11` 安装兼容范围，但不代表对旧版进行本轮验证。未执行 `npm publish`。

## 一、为什么 v6 没有根治

v6 在 orchestrator 中按“每个 commentary item 的完整字符串”去重。它能处理两个 item 的整段文本完全相同，却把每个 item 内容当成不可分割的原子。

真实过程有更多组合形态：单个当前快照本身可能重复某一行；不同快照可能只有部分段落重叠；多个真实工具事件在隐私过滤掉命令、参数和路径后，可能分别变成相同的 `🧰 Tool Call` 或 `🛠 Exec`。Bot WS 旧实现把 preamble、structured-item 和 Fast 的最新快照直接按类别拼接，最终气泡仍会保留这些重复可见行。

因此 v6 的问题不是 `Set` 本身失效，而是去重位置和原子粒度不对：它在最终用户可见气泡形成之前过早按整段处理。

## 二、最终气泡统一去重

- 新增 `composeTransientProgressSnapshot`，在 Bot WS 最终瞬态快照层读取 preamble、structured-item 和 Fast 的当前值。
- 每个值按换行展平，行首尾空白清理后使用本次快照级 `Set<string>` 做精确去重，再按类别重新组合；保留第一次出现的顺序。
- 不做包含判断、编辑距离或语义相似度匹配。只有最终显示完全相同的非空行才折叠。
- `transientProgressTextByKind` 继续保存每类过程的原始当前快照，每次更新都重新计算可见结果。后续新增或变化的行可以出现，从所有当前快照消失的行也会消失。
- 流式气泡、流窗口失效后的循环状态、回调冲突后的强制主动推送都读取同一份 `latestTransientProgressText`，不会再出现某条路径去重、另一条路径重复。
- 多次真实工具调用若脱敏后成为完全相同的通用标签，只显示一行。由于这些标签已不含调用身份或参数，重复行无法向用户提供额外信息；工具执行和日志不受影响。

正文、reasoning、preamble 源状态、正文/瞬态书签、ACK、final、媒体路径均未修改。成功 final 继续只显示最终答复；没有 final 时仍保留最后一次可见过程。

## 三、按用户反馈形态红绿验证

新增测试直接构造两类实测气泡：

- preamble 中包含两条完全相同的长句；旧实现第一帧明确显示两次。
- structured-item 随后包含两组 `Tool Call / Exec`；修复后每个通用标签只显示一次。

同一用例继续更新 preamble，新增“整改方案已生成”；新行可以正常出现。最后发送 final，断言最终气泡不包含长句或工具状态，守住既有瞬态收口设计。
