# 3.0.0-11（2026-09-12，LinKy fork）

本版有两部分：对 3.0.0-7 至 3.0.0-10 的对抗式审核跟进（三处），以及现网 3.0.0-10 反馈的两个通知类问题的修复。**同一版本号重新发布**：首次 3.0.0-11 包（SHA-256 `c45edf1f…fec04`）只含审核跟进，未部署现网，已被本包取代，tag `released/3.0.0-11` 已移到新提交。生产 OpenClaw 仍为 `2026.7.1-2`。

## 现网反馈修复（3.0.0-10 现网）

- **待机很久后收到「之前任务还在处理中，新指令冲突啦…」，真正的回答从未到达。** 这句话在 OpenClaw 对同一条消息连续两次返回「零结果」（未启动 run、未接管、无输出、无 fallback 标记）时发出，插件先等 500 ms 重试一次。零结果有两种来源插件区分不了：会话上确有活跃回复操作，或核心的入站去重命中（同 msgid 20 分钟内出现过 / 正在处理）。现在只有核心的 embedded run 登记表确实报告该会话有 run 时才说「任务还在处理中」；否则改发「（这条消息没有被处理，可能与上一轮收尾冲突或被判为重复，请重新发送）」。根因未定案：需要事发时该会话上一轮的 `error-final` / `deferred-close-declined` / takeover 类日志，见 SESSION_HANDOFF 第 5 节。`welcomeText` 已配置的账号 `enter_chat` 走静态欢迎语、不占会话，已排除。
- **思考十几分钟后只收到一条「（回复完毕）」。** 核心交来的 final 正文为空、但气泡里已经显示过思考内容时，插件原本把正文直接置为完成标记，流窗口已死就作为独立消息推出。现改为「（本轮没有生成正文回复，可重新发送一次指令）」。上游为何交空 final 从现有信息判断不了（常见是整段输出都是 `<think>` 块或干脆没写正文），本版只修插件侧的表达。
- **通知类 final 不再追加「（回复完毕）」。** 两张现网截图里通知下面都跟着一个标记：死窗回退推送与 final 推送重试对所有非 deferred 正文追加标记，通知类 final（任务冲突 / 未处理 / 无正文）现在通过 `channelData.wecomNoticeFinal` 标记跳过。

## 对抗式审核跟进

- **空流收尾不再显示「⏳ 正在思考中...」。** 3.0.0-7 为消除空白气泡，把从未画过预览的流收在 placeholder 文案上，结果「正在思考中」成了气泡的永久终态：答案已经作为独立消息推送（`wecomExternalFinalDelivered`）或两条消息被合并处理时，用户看到的是一个卡住的机器人。现在这类收尾帧改为 `（回复完毕）`，只表示这个气泡结束了；画过任何预览的气泡仍收在预览内容上，流窗口失效与 supersede 分支不变。
  - 有意识的取舍：deferred 回合（答案在另一个气泡或稍后的推送里）若没有预览，收尾帧同样是 `（回复完毕）`。「deferred 回合不挂（回复完毕）」这条既有规则针对的是正文与进度推送（答案还会跟在后面），关闭一个空气泡不在其列。
- **`~` 媒体路径用例与 Vitest pool 解耦。** 「expands ~」用例原先改写 `process.env.HOME`；threads pool 下 worker 线程的 `process.env` 是副本，libuv 读不到，`os.homedir()` 返回真实家目录，用例必红。改用 `vi.spyOn(os, "homedir")`。生产运行在主线程，行为不变。
- **deferred 媒体用例补齐顺序断言。** 「flushes media deferred by a block before closing a deferred turn」现在断言终止帧在全部附件上传之后发出，并收在用户已见正文上。

## 评估后不改

- **reasoning 合并不按 `isReasoningSnapshot` 分叉。** OpenClaw 2026.7.1-2 的 embedded 车道（`selection` / `btw`）发的是当前思考段的累计快照且不带该标记，只有 CLI 车道带；3.0.0-9 的末行前缀启发式与核心自己的 `mergeReasoningProgressText` 思路一致，已覆盖现网日志形态。
- **单个 `~` 继续保留。** 企微 markdown-v2 子集（群机器人文档 path/99110 的 markdown_v2 节；智能机器人长连接文档 path/101463 的 markdown.content 链接同一节）只列标题、字体（斜体 / 加粗）、列表、引用、链接、分割线、代码、表格，没有任何删除线语法，`~~` 与 `~` 都没有。官方插件 Bot WS 车道不改写模型 Markdown。`>`、有序 / 无序列表、表格都在子集内，3.0.0-8 把块级步骤换到独立行得到的是文档定义的渲染。
