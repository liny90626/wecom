# 3.0.0-12（2026-09-29，LinKy fork）

主动发起的消息支持模板卡片。生产 OpenClaw 仍为 `2026.7.1-2`。本包已在现网验收通过（2026-09-29），发布包与验收包逐字节一致。

## 问题

答疑回访需要 agent 主动给用户推评分卡片。现网实测（2026-09-26、09-29）：

- agent 在**回复用户刚发的消息**时输出卡片代码块，用户收到可点的卡片；
- agent **主动发起**（定时提醒、`message` 工具），即使 1 小时内刚聊过，用户收到的是裸 JSON。

根因在插件内部，不在企微：卡片抽取只接在回复链路的收尾（`src/transport/bot-ws/reply.ts`）。主动出口 `wecomOutbound.sendText`（`src/outbound.ts`）把整段正文按 markdown 发送，没有识别卡片的逻辑。回复链路发卡用的本来就是长连接的主动推送命令（`aibot_send_msg`），所以企微侧的能力早就通了。

## 改动

- **主动出口识别卡片**：`sendText` 正文里有合法卡片代码块（`card_type` 是五种之一）时，先逐张推卡片，再把剩余文字按 markdown 发送。卡片抽取、简化格式转换、字段修正复用回复链路的 `extractTemplateCards`，两边不分叉。普通 JSON 代码块不受影响。
- **失败即报错、不发裸 JSON**：以下情况 `sendText` 抛错，调用方（`message` 工具）拿到原因。任何一张卡片发出之前失败的，什么都不发：
  - 卡片缺核心字段（如 `vote_interaction` 没有选项）；
  - 目标会话走 Agent API 或上下游企业路径（这两条路径上的卡片回调回不到这个会话）；
  - WS 未连接，或运行时不支持推卡片；
  - 企微拒收。错误里带 `errcode` / `errmsg`：SDK 拒绝时给的是原始回执帧，现在转成可读的错误。
- **卡片先于文字发送**：卡片被拒时提示语也不会发出，重试不会让用户收到两遍。卡片接在已有的 Bot WS 文本发送函数里，路由、连接检查与剩余正文的发送与普通主动消息完全一致；整条消息只有卡片时不再补发空 markdown。
- **返回 task_id**：`messageId` 为 `bot-ws-card-<task_id>`，多张用逗号分隔。解析器会给 `task_id` 追加时间戳与随机串，台账应以返回值为准。
- **卡片抽取与校验**：新增 `planProactiveTemplateCards`（`src/capability/card/parser.ts`），只在正文含卡片代码块时才读开关与解析，不含卡片的消息路径与之前逐行一致。
- **推送句柄新增 `sendTemplateCard`**（`src/transport/bot-ws/sdk-adapter.ts`）：带单聊/群聊标记，发送成功后登记卡片缓存，点击回调照常把卡片改成「已提交」，并把选项 id 还原成原文。消息体构造 `buildTemplateCardMessageBody` 与回复链路共用。
- **开关 `bot.proactiveTemplateCards`**：账号级，默认开启；设为 `false` 回到旧行为。回复链路发卡不受影响。
- **agent 指引**：会话注入的卡片指引与 `wecom-send-template-card` 技能补充主动发送的用法与失败处理。

## 已知限制

- 核心对出站正文按 20480 字节预分片。卡片代码块如果恰好被切开，该片会按旧行为作为文本发出。单张卡片 JSON 远小于这个上限，只有超长正文加卡片时才可能遇到。
- 卡片缓存仍只在进程内（24 小时 / 300 张）。网关重启后点击旧卡片，回调里只有原始选项 id（如 `s1`），卡片也不会变成「已提交」，用户可能重复提交，台账需按 `task_id` + 用户去重。
- 「几天未互动的用户能否主动推送」取决于企微对 `aibot_send_msg` 的会话限制，本版无法在代码侧确认，需现网验证。
- **只认代码块围栏**：卡片 JSON 必须包在 ```json 代码块里，裸 JSON 按普通文字发出。现网首轮验收就栽在这里：验证指令经企微窗口转发时，代码块被客户端渲染掉，agent 收到并发出的是不带围栏的 JSON（日志 `sendText:path-bot-ws textLen=302`，带围栏应约 313）。给 agent 的指令里要用文字描述围栏，或让 cron 负载直接存放带围栏的正文。是否放宽到识别裸 JSON 对象，本版未做。
