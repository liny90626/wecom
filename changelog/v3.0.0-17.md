# 3.0.0-17（2026-10-19，LinKy fork）

一轮对抗式检查后的稳定性与速度修复，共 8 项。没有现网故障报告驱动，均为读代码核实后的缺陷；每项都有用例，并已逐项回退源码确认修复前会失败。

## 稳定性

- **长时间断网后 Bot WS 不再永久掉线。** 原先 SDK 自身重连 10 次、插件再重启适配器 10 次后就放弃（约 55 分钟），而 agent 回调让账号看起来仍然在线，只能手动重启网关。现在不设次数上限，退避间隔仍封顶 5 分钟，网络恢复后会自行连回（`src/capability/bot/service.ts`）。
- **Agent API token 失效后不再连续失败最多两小时。** token 缓存键不含 secret，也没有处理 40001 / 40014 / 42001：改了 corp secret 或企微提前作废 token 后，旧 token 会一直用到名义过期。现在缓存键带 secret 指纹；遇到这三个错误码会丢弃 token、重新获取后重发一次（这三个码表示请求被拒、没有执行，重发安全）。`sendText`、`sendMedia`、`uploadMedia`、文档、日程都走这条路径（`src/transport/agent-api/core.ts`）。
- **文档 / 日程不再重复创建。** 原先所有错误（含超时、业务错误码）都重试 3 次；超时但企微已经执行的 `create_doc`、`schedule/add` 会建出 2~3 份。现在只在 token 被拒时重发一次。代价：读接口遇到瞬时网络错误不再自动重试，由模型自行再调用（`src/capability/doc/client.ts`、`src/capability/calendar/client.ts`）。
- **系统事件帧不再中止无人认领的 run。** 3.0.0-16 的保护只看待处理的 Bot WS 用户回合；后续续跑、cron、announce 这类 run 没有待处理记录，`auth_change_event` 仍会在派发前把它中止。现在系统帧遇到会话里有活跃 run 时直接跳过（日志同为 `[wecom-b3] system-inbound-skipped`，带 `activeRunSessionId`）（`src/runtime/dispatcher.ts`）。

## 速度

- **工具调用前的最后一段正文不再拖到最终回复才出现。** 预览更新有 1.5 秒节流，节流窗口内到达的正文块被丢掉，要等下一个事件才画出来，工具调用前的那一段往往一直等到 final。现在窗口一结束就补画一帧（同一时间只有一个定时器，回复结束时清理，预览冻结后不走这条）（`src/transport/bot-ws/reply.ts`）。
- **不再每个回复分块写一行同步日志。** `[wecom-runtime] session …` 只在 running / owner / connected / authenticated / lastError 变化时写；状态上报照旧每次都发（`src/app/account-runtime.ts`）。

## 内存与附件

- 下载响应体时去掉逐块复制，峰值内存从约 3 倍文件大小降到 2 倍；解密时 `final()` 为空不再整块拼接；下载返回非 2xx 时先释放连接再报错（`src/http.ts`、`src/media.ts`）。
- **恰好等于大小上限的文件不再被拒。** 加密体比原文件多最多 32 字节 PKCS#7 填充，原先按文件上限限制加密体。现在按「上限 + 32」下载，解密后按文件大小精确判断（与 webhook 车道一致）（`src/shared/media-service.ts`）。
- **首个附件的下载随回合中止一起停止。** 其余附件早已传入中止信号，首个没有，回合被接管或准备超时后还会在后台下载最多 45 秒（`src/shared/media-service.ts`、`src/runtime/session-manager.ts`）。

## 核实后未改

风险低或依赖配置，记录在交接文档 2.-17：一轮最多 8 个附件、每个按完整 `mediaMaxMb` 下载，没有整轮总量限制；多个用户共用一个会话（如 `session.dmScope="main"`）时一人的消息会中止另一人的任务；最终回复分片重试期间到达的系统事件会取消剩余重试（生产配了 `welcomeText`，只剩 `auth_change_event` 可能触发）；Agent 媒体固定 15 秒超时；MCP 地址缓存遇 401/403 不失效等。
