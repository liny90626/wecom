# 3.0.0-5（2026-09-05，LinKy fork）

发布标签 `released/3.0.0-5`。这是一个**回退版本**：代码回到 `2.7.260-26` 的 Bot WS 车道，带上两个此前未发布的修复，只从上游 `v3.0.0` 移植治理层的精华，并把「生产配置形状」写成回归测试。版本号规则改为 `3.0.0-<构建号>`，构建号从 5 起；`3.0.0-v1`、`3.0.0-v2` 撤回。

## 一、为什么回退

`3.0.0-v1` 把整棵树替换成上游 `v3.0.0`。上游 v3 不是 2.7.260 的增量，而是以腾讯官方插件 2026.8.17 为主线的重建，两件事在现网上同时暴露：

1. **起不来。** 上游 v3 的配置 schema 对未知键零容忍，现网配置里留着 2.7.x 时代的 `mediaMaxMb`、`streaming`，账号里是嵌套的 `bot` / `agent`，CLI 直接以 `must not have additional properties` 退出。`3.0.0-v2` 放宽了 schema，但 `openclaw plugins install` 启动时先用已装的 v1 校验配置，同一个错误让 v2 根本装不上。
2. **长任务体验倒退。** 官方车道在流窗口约 6 分钟关闭后不再有任何反馈，直到 final 一次性推送；本 fork 车道的 8 分钟状态帧、90 秒工具沉默看门狗、死窗后 20 秒正文推送、思考窗口、新消息接管都不存在了。

结论：整树替换违背「最小改动、行为兼容」的维护原则。回退，并把 v3 值得要的部分手动合并进来。

## 二、本版包含什么

- **2.7.260-26 车道 + 两个未发布修复**
  - `5bcbd05` 运行时上下文围栏：三条入站车道对 `<<<BEGIN_OPENCLAW_INTERNAL_CONTEXT>>>…<<<END_…>>>` 转义成核心自己用的 `[[OPENCLAW_INTERNAL_CONTEXT_BEGIN]]` 形态，过程步骤与思考流剥掉围栏块。见 `SESSION_HANDOFF.md` 第 2.-5 节。
  - `c39ace2` compat 工作区移出仓库树（`~/.cache/wecom-openclaw-compat/`），8.x/9.x 的 typecheck 不再借用钉住的 7.1-2 声明。
- **从上游 v3.0.0 移植的治理层**
  - `THIRD_PARTY_NOTICES.md`：官方插件代码的 MIT 归属，随包发布。
  - `UPSTREAM_BASELINE.json` + `scripts/check-official-updates.mjs` + `npm run upstream:check`：记录官方对账基线 `3b1cbe3`（2026.8.17），一条命令看官方 main 是否有新提交。仓库配置只读 `official` 远端，push URL 为 `DISABLED`。
- **生产配置形状回归**（`src/config/production-shape.test.ts`）：四个账号、嵌套 `bot`/`agent`、顶层 `mediaMaxMb` / `streaming` / `media.localRoots`，断言 schema 放行、四个账号都解析出 Bot WS 与 Agent、默认账号正确、无冲突。以后任何 schema 改动都要过这一关。

## 五、现网升级：CLI 被 v1 锁死时怎么装

装过 `3.0.0-v1` 的机器上，`openclaw plugins install` 会先用已装插件的 schema 校验配置，校验失败就退出，任何包都装不上；`openclaw doctor --fix` 不能跑，它会把配置改成 v3 的扁平形状，本车道就读不到凭据。手动换目录即可，配置文件不用改。以下步骤已在 OpenClaw 2026.7.1-2 的隔离状态目录里用真实的 v1 包完整演练过（装 v1 → 复现锁死 → 换目录 → 校验通过 → 网关启动）。

1. **不要先停网关。** 磁盘上换好再重启，重启失败的窗口就不存在。
2. 备份配置：`%USERPROFILE%\.openclaw\openclaw.json`。
3. 备份插件目录到 **`extensions\` 之外**，例如 `%USERPROFILE%\.openclaw\wecom-plugin-backup-v1`。备份若留在 `extensions\` 里，OpenClaw 会把它当第二个插件加载并报 `duplicate plugin id detected`，加载到哪一份不确定。
4. 在 `extensions\wecom` 里删掉除 `node_modules` 以外的所有内容（`dist`、`skills`、`*.md`、`*.json`、`index.ts`、`LICENSE`）。保留 `node_modules`：v1 装好的依赖满足本版要求（aibot-node-sdk 1.0.7、@wecom/cli 1.2.0、fast-xml-parser 5.x、undici 7.x，含 Windows 平台 CLI 包）。
5. 把 `yanhaidao-wecom-3.0.0-5.tgz` 解开（Windows 自带 `tar -xzf`），将 `package\` 目录里的全部内容复制进 `extensions\wecom`。
6. 网关还在跑的时候先自检：`openclaw config validate` 应输出 `Config valid`；`openclaw plugins inspect wecom --runtime --json` 里 `version` 为 `3.0.0-5`、`diagnostics` 为空；`openclaw channels list` 列出全部账号 `configured, enabled`。三条都过再重启。
7. 重启网关。之后 `openclaw plugins install` 恢复可用，下次升级照常用它。

安装后先看：四个账号是否都 `authenticated`；发一次文件；跑一次超过 6 分钟的长任务，确认 8 分钟状态帧与死窗后正文推送回来了。
