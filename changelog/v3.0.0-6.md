# 3.0.0-6（2026-09-05，LinKy fork）

发布标签 `released/3.0.0-6`。在 `3.0.0-5` 之上只修一件事：**`MEDIA:` 指令发出的文件在现网静默丢失**，也就是用户在 `2.7.260-26` 上反馈的「agent 说文件发了，实际没到，再要一次才到」。

## 一、根因（现场日志分析 + 三个版本解包对比）

- `2.7.260-25` 及更早：本地媒体路径校验调用 OpenClaw SDK 的 `assertLocalMediaAllowed`，文件与根目录都取 realpath 再比较，然后 `readFile`。
- `2.7.260-26`（2026-09-02 12:51 起）：为兼容 2026.8.x（该函数被私有化），改用 fs-safe 的 `readLocalFileFromRoots`。在 Windows 现网上它把合法路径也判为「不在允许目录内」，其中包括 OpenClaw 自己的 outbound 媒体目录。
- `MEDIA:` 指令这条链路里，失败只被拼进 final 文本、**没有任何日志**；正文早已作为推送到达，用户看到的就是「已发送」的正文和一个没到的文件。`message` 工具那条链路多合并了核心传入的根目录，恰好能过，所以「再要一次」有时成功。
- 旁证：同一台机器上 OpenClaw 核心的 image 工具对 D 盘 workspaces 路径也报 `not under an allowed directory`，是同一个读取器在 Windows 上的表现。
- 影响范围：9/2 12:51 至今所有走 `MEDIA:` 指令的文件；`3.0.0-5` 沿用 -26 的这段代码，同样受影响，**不要安装 3.0.0-5**。

## 二、修法

`src/transport/bot-ws/media.ts`：不再经过 `readLocalFileFromRoots`，在本地重写 -25 的语义：文件与每个根目录都取 realpath，`path.relative` 判断包含关系（Windows 上不区分大小写），符号链接指向根外即拒绝，不存在的根跳过，文件系统根不算，通过后 `readFile`。OpenClaw 媒体目录仍算作允许根；`~/` 路径按技能文档展开。不依赖 2026.8.x 私有化的 SDK 函数，两条线一份代码。

`src/transport/bot-ws/reply.ts`：`MEDIA:` 链路的媒体发送成功与失败各加一行日志（`[wecom-media] sent …` / `[wecom-media] send-failed … reason=…`）。失败文本照旧拼进 final；日志里不再是空白。

复现用例（`media.test.ts`）：符号链接根目录下的文件可读、根内指向根外的符号链接被拒、`~/` 展开；原有「允许根内可读 / 根外拒绝」两条保留。Windows 的路径大小写 / 盘符差异无法在 Linux 上复现，靠回到 -25 现网验证过的语义来兜。

## 四、现网安装

步骤与 [`3.0.0-5`](./v3.0.0-5.md) 第五节完全相同，把包名换成 `yanhaidao-wecom-3.0.0-6.tgz`：不停网关，备份放在 `extensions\` 之外，只保留 `node_modules` 换掉其余文件，`config validate` / `plugins inspect` / `channels list` 三条自检通过再重启。不要跑 `doctor --fix`。

装上后：让 agent 用 `MEDIA:` 发一个文件，日志里应出现 `[wecom-media] sent … type=file`；再试一个 D 盘路径的文件，看是 `sent` 还是 `send-failed reason=…`，把这行发回来。
