# v3.0.0-v2（2026-09-05，LinKy fork）

发布标签 `released/3.0.0-v2`。修一件事：**3.0.0-v1 装到 2.7.x 的现网配置上起不来**。

## 一、现象与根因

在 OpenClaw 2026.7.1-2 上安装 3.0.0-v1 后 CLI 直接退出：

```text
Config validation failed: channels.wecom: invalid config for plugin wecom: must not have additional properties: "mediaMaxMb", "streaming"
```

这两个键不是新插件需要的，恰恰相反：`mediaMaxMb` 是 2.7.x fork 的媒体上限别名，`streaming` 是更早留下、任何版本都没读过的键。2.7.x 的 schema 对未知键宽容，它们一直无害地留在配置里；上游 v3.0.0 把 `channels.wecom` 及各级对象改成 `additionalProperties: false`，一个多余的键就让整段配置失效、网关拒绝启动。3.0.0-v1 没有拿 2.7.x 时代的真实配置验过，这是本 fork 的失误，不是使用者的配置问题。

## 二、修法：插件不读的键不该阻止启动

- `src/config-schema.ts`：`channels.wecom`、账号、`agent`、`media`、`network` 五个对象只校验插件真正读取的键的类型，多余的键一律放过，运行时按默认值工作。`groups.<id>`、`dynamicAgents`、`cli`、`upstreamCorps.<id>` 的键与 2.7.x 相同，保持严格。
- `openclaw.plugin.json`：冷启动校验用的是清单里的这份 schema，此前它比运行时少了 `name`，现在由运行时 schema 生成，测试守住两者一致。
- `src/doctor-contract.ts`：`openclaw doctor` 识别 2.7.x fork 独有的键并在 `--fix` 时处理：
  - `mediaMaxMb`（顶层与账号级）→ `media.maxBytes`（字节，已有显式值时不覆盖）
  - `media.localRoots` → `mediaLocalRoots`（合并去重）
  - `mediaDownloadTimeoutMs`、`media.downloadTimeoutMs`、`network.mediaDownloadTimeoutMs`、`routing`、`streaming` → 删除，3.x 不再读取，每项写出原因

复现用例：`config-schema.test.ts`「does not refuse to start on keys the 2.7.x fork accepted」（现场那份配置的形状）、「validates the doctor-migrated shape of a fork-era config」、「ships the same schema in openclaw.plugin.json for the cold path」；`doctor-contract.test.ts`「migrates what has a 3.x equivalent and removes what has none」「keeps an explicit media.maxBytes over the legacy mediaMaxMb」。修复前 5 条红，修复后全绿；类型错误（`botId: 123`、非法 `dmPolicy`）仍然被拒绝。

## 三、升级动作

1. 安装本版后直接启动即可，旧键不再阻止启动。
2. 建议随后执行 `openclaw doctor --fix --non-interactive`，把 2.7.x 的键迁走或删掉，让配置回到 3.x 的形状。
3. 入站附件大小上限现在跟随 OpenClaw 的 `agents.defaults.mediaMaxMb`（未设置时 5 MB），2.7.x 的 80 MB 默认值不再存在；要接收更大的文件请设置该项。
